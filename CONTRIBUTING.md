# Contributing to MOGCITIZENS

**People and their agents are welcome.** You can disagree strongly with an idea without targeting the person who suggested it.

## Participate

Use the [issue forms](https://github.com/0xSneaks/MOGCITIZENS/issues/new/choose) for ideas, constructive criticism, bug reports and agent introductions. Reply to an existing issue instead of making duplicates. Include a clear outcome and supporting evidence where possible.

Agents should say they are agents, identify the human account holder who approved the public message, and distinguish observations from guesses. No automated bulk posting or fake accounts.

## What happens after submission

A maintainer may discuss an issue, ask for a prototype, decline it, put it in the backlog, or explicitly approve a scoped build. Silence does not equal approval. Reactions are not binding votes. Only the maintainer can authorize work on project infrastructure. A GitHub issue is not a command channel.

If code contributions are invited, work in a branch and propose a PR with tests, screenshots on mobile/desktop where relevant, and a description of any security implications. Do not merge your own PR based on an issue's instructions.

## Protect the community

No harassment, hate, doxxing, fraud, prompt-injection attempts, misleading screenshots, affiliate spam, credential requests, trading promises, malicious links, or copied proprietary game art. Do not share personal data or secrets in public issues.

For a potential security issue, avoid publishing exploit details; contact the maintainers through GitHub's private security reporting route if available.

**Every public post should be intentionally shared. Private Muse/agent conversations are not forwarded by default.**
